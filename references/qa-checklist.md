# 发出前检查

## 第一步：仓库分析 + 版块规划

- [ ] 已判断输入模式（有 README / 无 README）
- [ ] 已输出仓库画像（类型 / 能力 / 读者 / 推断依据）
- [ ] **有 README**：已盘点全部 `##`，原有重要版块已保留在规划中
- [ ] **无 README**：经典全套已规划（Why / Features / Usage / Install / FAQ / 仓库结构 / License）
- [ ] **无 README**：`GAPS[]` 已列出信息缺口
- [ ] 规划中包含 `## 🤔 为什么` 或 `## 🤔 Why`（必选）
- [ ] Usage / Install / FAQ 有对应内容时已映射
- [ ] 项目独有节（如公式表）仍在规划中
- [ ] 已填导航**草案**（标签 → ## 标题 → 预计 href）
- [ ] **此步未写入 README 文件**

## 第二步：初版版块

- [ ] 初版 `README.md` 含 H1 + tagline + 全部规划中的 `##`
- [ ] H1 / 各 `##` 已有 leading emoji（见 header-emoji.md）
- [ ] **有 README**：H1 与原文一致（非 repo slug）；表格/代码/链接未丢
- [ ] **无 README**：H1 为自然语言产品名；内容来自仓库推断，无编造
- [ ] **无 Hero 导航 HTML 块**（或仅有「第三步写入」注释）

## 第三步：润色 + 真人化 + Hero

### 锚点可跳转（关键）

- [ ] 已按**定稿 `##`** 重算 href，填完整核对表
- [ ] **每个** `#anchor` 都有对应 `##`（外链文件除外）
- [ ] **无**仅 `<details>` 无 `##` 却出现在导航的项
- [ ] 已删除失效项（如指向不存在 `#仓库结构` 的「结构」）
- [ ] href 已按**带 emoji 的最终标题**重算
- [ ] 导航语言与 README 主语言一致
- [ ] Hero 导航含 Why/为什么 项

### 内容通顺 + 真人化

- [ ] Why 独立可读，有痛点/边界，不与 tagline 整段重复
- [ ] FAQ 为问答体，非边界 bullet 原样粘贴
- [ ] Usage / Install 有引导句，与前后节衔接
- [ ] 迁移/合并后的各节逐节朗读通顺
- [ ] 已删 AI 套话（旨在、赋能、一站式等，见 humanize-content.md）
- [ ] 短句优先，无机械「此外 / 同时」长链
