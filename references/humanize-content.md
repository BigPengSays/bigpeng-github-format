# 真人化润色

第三步的一部分：**让 README 读起来像人写的**，不是模板生成的。与 [content-polish.md](content-polish.md) 配合——content-polish 管连贯与结构，本文件管语气与去 AI 腔。

**不依赖外部 humanizer skill**；规则内置于此。

---

## 原则

- **保留事实**：命令、路径、数字、表格数据不改  
- **改表述**：套话、空泛形容词、机械过渡  
- **一句一事**：短句优先；一段只说一件事  
- **读者视角**：FAQ 用读者会问的口语问句  

---

## 必删套话（中文）

出现即改或删：

| 套话 | 改法 |
|------|------|
| 旨在 / 致力于 | 直接说做什么 |
| 赋能 / 助力 / 一站式 | 删，换具体能力 |
| 显著提升 / 大幅优化 | 有数据写数据，无则删 |
| 众所周知 / 不难发现 | 删 |
| 此外 / 同时 / 与此同时 连用 | 拆句或删连接词 |
| 综上所述 | 删；最后一段直接给结论 |
| 为您提供 / 帮助您 | 改「你可以…」或祈使句 |

## 必删套话（英文）

| 套话 | 改法 |
|------|------|
| designed to / aims to | 直接动词开头 |
| seamlessly / robust / powerful | 删或换具体描述 |
| leverage / utilize | 用 use |
| comprehensive solution | 说具体包含什么 |
| It is worth noting that | 删，直接陈述 |

## 各节真人化要点

### Why

- 第一句：**场景或痛点**（「README 信息全但不好扫」）  
- 避免「本项目的目的是…」开头  
- 说清做什么、不做什么，用平实口语  

### Features

- 节首一句说「这节列什么」  
- 列表项用动词开头（「保留原 H1」「验证锚点可跳转」）  
- 少形容词堆砌  

### Usage

- 写「对 Agent 说…」或「运行…」  
- 示例前后各一句说明，不要只贴代码块  

### Install

- 命令前一句交代前提（「克隆仓库后：」）  
- 分平台用 `###`，不要一大段 prose  

### FAQ

- **必须**读者口吻问句：`能重写我的 README 吗？`  
- 答句直接、短；不要「是的，本项目…」  
- 边界 bullet 第三步全部改问答，禁止保留「边界：」「限制：」小标题列表  

---

## 通顺 + 真人化自检

每节改完后过一遍：

1. 朗读：像对人说话吗？  
2. 删套话：上表词汇是否还在？  
3. 重复：tagline、Why、FAQ 是否说了三遍同一件事？  
4. 具体：抽象词是否都能换成动作或例子？  
5. FAQ：是问答还是仍在列 bullet？  

任一项否 → 继续改，再进入 Hero 定稿。

---

## 禁止

- 编造功能、数据、用户评价  
- 改 H1 产品名  
- 为「更像人」而加网络梗、过度口语（「绝绝子」等）  
- 覆盖或简化表格、代码块内容  

真人化完成后，按 [nav-design.md](nav-design.md) 验证锚点，再写 Hero HTML。
