# Header Emoji 备选池

美化后的 **H1 与各 `##` 标题**应带**一个**贴切的 leading emoji。同一 README 内**不重复**使用同一 emoji；**不要**每份 README 都固定用 🤔 / 🚀。

## 选取规则

1. **第一步**定稿各节标题文案后，为每节从下方备选池**各选 1 个** emoji  
2. **选取方式**：结合项目领域 / 语气挑最贴切的；同领域多仓库时**轮换**备选，避免总选池内第一项  
3. **已有 emoji**：原标题 / 原 `##` 已带合适 emoji → **保留**，不强行替换  
4. **无 emoji**：从对应槽位备选池补 1 个，写在标题**最前**，格式 `## {emoji} {标题}` 或 `<h1>…{emoji} 标题…</h1>`  
5. **H1**：无 README 推断标题时必加；有 README 时原文无 emoji 则按领域池补  
6. **License**：一般**不加** emoji  
7. 选完后填入核对表，**第二步**按带 emoji 的最终 `##` **重算 href**

## H1 备选（按项目领域）

| 领域 | 备选（任选一） |
|------|----------------|
| Agent / Skill | 🧩 🤖 ✨ 🛠️ 🪄 |
| GitHub / 文档 / README | 📝 📄 📋 ✨ 🗂️ |
| 写作 / 内容 / 公众号 | ✍️ 📱 📰 🎯 ✨ |
| 图片 / 设计 | 🎨 🖼️ 🎭 ✨ |
| 开发工具 / CLI | ⚙️ 🔧 💻 🛠️ |
| 数据 / 分析 | 📊 📈 🔍 |
| 通用兜底 | ✨ 🚀 📦 🌟 |

示例：`📝 GitHub README 排版 Skill`、`🧩 微信公众号爆款 AI 选题 Skill`

## 标准 `##` 槽位备选

| 槽位 | 中文节名示例 | 备选（任选一） |
|------|--------------|----------------|
| **Why** | 为什么 | 🤔 💡 🎯 ✨ 🧭 |
| **Features** | 功能 | ⚡ 🛠️ ✨ 📦 🎨 |
| **Usage** | 使用方法 | 🚀 📖 💻 ▶️ 🎮 |
| **Install** | 安装 | 📥 ⬇️ 🔧 ⚙️ 🧲 |
| **FAQ** | 常见问题 | ❓ 💬 🙋 🆘 📋 |
| **Structure** | 仓库结构 | 📁 🗂️ 📂 🗃️ |
| **Examples** | 示例（若独立成节） | 💡 📝 🧪 ✏️ |

**禁止**：六个标准节全部用 🤔🚀📥 同一套「默认三连」；至少 Why / 功能 / 用法 应来自**不同**备选。

## 项目独有节

原文保留的独有 `##`（如「爆款标题的 7 种公式」）：

| 内容类型 | 备选 |
|----------|------|
| 公式 / 规则 / 清单 | 📐 📋 🧮 ✏️ |
| 模板 / 样例 | 📝 🧩 📎 |
| 原理 / 工作流 | ⚙️ 🔄 🧠 |
| 对比 / 评测 | ⚖️ 🔬 📊 |
| 无明确类型 | ✨ 💡 📌 |

已有 emoji 的独有节标题 → 保留。

## 自检

- [ ] H1 与每个 `##` 各有 1 个 emoji（License 除外）  
- [ ] 同一 README 无重复 emoji  
- [ ] 未全仓库固定使用 🤔 为什么 + 🚀 使用方法  
- [ ] href 已按**最终带 emoji 的标题**重算
