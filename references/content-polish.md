# 版块内容润色

**第三步**的一部分：各 `##` 节不仅要**信息完整**，还要**读起来通顺**。节名对齐、首段拆入 Why、边界改 FAQ 时，上下文容易断——**第三步必须逐节过一遍**。

真人化（去 AI 腔）见 [humanize-content.md](humanize-content.md)；本文件管**连贯性与结构**。

## 何时润色

| 情况 | 处理 |
|------|------|
| 首段拆入 Why，Why 节只剩半句话 | 补痛点、能力范围、适用对象，写成完整段落 |
| Hero tagline 与 Why 重复 | tagline 留一句；Why 展开，不整段复制 |
| 「边界」bullet 直接改名 FAQ | 改成问答体，见下表 |
| 多节合并（如简介 + 背景 → Why） | 去重、理顺因果，删过渡套话 |
| 项目独有节（公式表等） | 保留表格/列表；仅润色节首引导句 |
| Install / Usage 从正文散落处迁入 | 补一句「如何开始」，与前后节衔接 |
| 第二步初版过渡生硬 | 补节首引导、节末收束 |

## 润色 ≠ 重写

- **保留**：事实、数字、命令、路径、表格数据、链接  
- **可改**：过渡句、节首引导、重复表述、bullet → 问答  
- **禁止**：编造功能、改 H1 产品名、用模板化英文套话覆盖原文  

润色完成后，按 [humanize-content.md](humanize-content.md) 做真人化自检。

## 各槽位润色要点

### Why

- 第一句点**痛点或场景**（读者为什么需要这个）  
- 第二段说**做什么、不做什么**  
- 若有路径/模式（如 A/B），简要交代  
- 独立可读，不依赖 Hero tagline  

### Features / 项目独有节

- 节首一句说明「这一节讲什么」  
- 表格、公式、列表**原样保留**；只修引导语  

### Usage

- 开头写清触发方式（对 Agent 说什么 / 跑什么命令）  
- 示例与说明之间加一句衔接  

### Install

- 平台分块清晰；命令块前有一句说明  

### FAQ

边界/限制类 bullet **不要**原样留在终版。改成读者会问的问题：

| 原 bullet 类型 | 问答示例 |
|----------------|----------|
| 不写正文 | **能写正文吗？** → 说明范围与替代 skill |
| 标题长度限制 | **标题多长合适？** → 字数 + 与推文标题分工 |
| 语料/赛道限制 | **只能写 XX 类吗？** → 来源 + 可迁移性 |
| 数据限制 | **没有 Star 数怎么办？** → 替代公式 |
| 使用模式 | **只有关键词怎么办？** → 对应路径/步骤 |

### Examples（外链）

- 正文 Usage 里提一句「更多见 examples/…」  
- 导航链到文件即可，不必重复全文  

## 通顺性自检（逐节朗读）

每改完一个 `##`，自问：

1. 不看 Hero / 上一节，本节第一句能懂吗？  
2. 本节末句与下一节首句逻辑接得上吗？  
3. 同一信息在 tagline、Why、FAQ 里是否重复三次？  
4. FAQ 是问答还是仍在列「边界」？  

任一项否 → 继续润色，再进入 [humanize-content.md](humanize-content.md) 与 Hero 定稿。
